# Codex用プロンプト例

このSkillを明示的に呼びたいときの依頼文例です。Codex CLI/IDE/アプリでSkillを選べる環境では `$ja-humanizer-codex` のように明示して使えます。

## 全面改稿

```text
$ja-humanizer-codex
以下の文章を、日本人読者に自然に届くように改稿してください。
意味・数字・固有名詞は変えず、AI臭い定型句、過剰な丁寧さ、抽象語、予定調和な結論を減らしてください。
媒体: note
読者: SaaS企業のマーケ担当者
トーン: ややカジュアル、でも軽すぎない
出力: 改稿文のみ

---
（本文）
```

## 診断だけ

```text
$ja-humanizer-codex
次の文章のAI臭さを診断してください。まだ改稿しないでください。
AI臭スコア、主因、優先修正箇所、一部修正例だけください。

---
（本文）
```

## 最小編集

```text
$ja-humanizer-codex
以下をedit-in-placeで直してください。
構成と意味は変えず、AIっぽい言い回し、語尾の単調さ、冗長な敬語だけを修正してください。
出力はBefore/Afterではなく、修正版のみでお願いします。

---
（本文）
```

## LP向け

```text
$ja-humanizer-codex
以下のLP文を、AIっぽい抽象語を減らして、人が読んで判断しやすい文章にしてください。
誇張は増やさず、読者の困りごとと行動変化が見えるようにしてください。

商品:
読者:
避けたい表現:
残したいキーワード:

---
（本文）
```

## 採用文向け

```text
$ja-humanizer-codex
以下の採用文を自然化してください。
「成長」「裁量」「挑戦」のような抽象語だけで終わらせず、どんな仕事・難しさ・向いている人が伝わるようにしてください。
事実は足さないでください。足す必要がある箇所は [要確認] としてください。

---
（本文）
```

## 技術記事向け

```text
$ja-humanizer-codex
以下の技術記事を、広告っぽさとAI臭を減らしてください。
前提条件、制約、詰まりやすい点が自然に伝わるようにしつつ、技術的な意味は変えないでください。

---
（本文）
```

## メール圧縮

```text
$ja-humanizer-codex
以下のメールをcompressで短くしてください。
失礼にならない範囲で、過剰な敬語・前置き・クッション言葉を削ってください。
相手: 既存顧客
目的: 日程調整
出力: 件名と本文

---
（本文）
```
